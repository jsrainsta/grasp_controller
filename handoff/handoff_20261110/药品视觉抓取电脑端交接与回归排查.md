# 药品视觉抓取电脑端交接与回归排查

2026 年 11 月 10 日 · 适用于已安装 11 月 9 日 Windows 联合调试基包的电脑。

**接手时请区分普通抓取和转腕试验。** 普通抓取用固定腕轴，已有独立实机持物记录。转腕试验会在悬停时转动 2 号舵机并按需张爪，拍照后结束。这次修复了转腕试验漏搜较低悬停姿态的问题，已有现场数据回放通过，仍待实机验证。自动转腕后继续下降、闭爪并夹稳，也仍待验收。

## 安装和覆盖

1. 结束正在运行的总控，确认机械臂空闲，并交代夹爪是否还持物。备份当前工程。使用交付文件 `grasp_pc_reviewed_update_20261110.zip`，将包内的 `k210_camera` 合并到旧工程同名目录，覆盖同名文件。若队友已经有其他本地修改，先备份并逐文件比较。
2. 保留旧工程的 `.venv`、`arm_service_review`、标定资源和 `k210_camera/controller_pc_fixed_placement_trial.json`。增量包会更新动作配置 `grasp_motion_fixed_placement_trial.json`，请核对总控配置的 `motion_profile` 指向它。若自己改过动作配置，请备份后核对差异。原基包的 `manifest.json` 用于识别旧版文件，本次包内的 `SHA256SUMS.txt` 用于核验新版增量。
3. 新电脑按基包的《开始调试》用 64 位 Python 3.13 建 `.venv` 并安装 `requirements-windows.txt`。已有环境可直接使用。树莓派仍运行已有机械臂 HTTP 服务，K210 USB 接当轮操作的 Windows 电脑。
4. 总控默认 `camera_port=auto`、`camera_baudrate=230400`。COM 号随电脑和 USB 口变化。若自动识别不到或有多个 CH340，在本机配置填写实际 COM。若板端是 115200 稳定版，电脑端也填 115200。机械臂串口的 9600 和 K210 波特率是两回事。

## 开机检查

以下命令在 Windows **CMD** 中运行。先开一个窗口建立 SSH 转发，用实际用户名和 IP 替换历史示例，并保持窗口开启。

```cmd
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18000:127.0.0.1:8000 pi@192.168.1.107
```

另开一个 CMD 并进入工程目录。先自检，再查机械臂连接，最后单独拍照。相机命令的波特率以现场固件为准。

```cmd
set "PY=.\.venv\Scripts\python.exe"
set "CFG=.\k210_camera\controller_pc_fixed_placement_trial.json"
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --check
curl.exe -sS --fail-with-body --max-time 5 http://127.0.0.1:18000/v1/arm/status
"%PY%" -X utf8 .\k210_camera\receive_photo.py --capture --baudrate 230400 --verify-jpeg
```

自检应为 `ready_for_connection_check: true`。机械臂状态要显示已连接、无活动任务。相机要保存完整、可解码的 640×480 JPEG。所有试验都由一台电脑发指令。开始前由现场人员确认夹爪内没有物体、手和线缆离开运动范围、小车停稳，且机械臂位于原观察位。

## 两条现场路线

### 普通抓取

空爪准备只在现场确认空爪后执行。新配置把目标从 385 调到 **372**，舵机读数较低表示更开。已有开度足够时会保留现状。腕轴须在中位附近。

```cmd
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --prepare-empty --confirm-empty --execute
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --preview
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --once grasp_%RANDOM%_%RANDOM% --execute
```

等预览输出 `path_preview_passed` 再执行第三行。实际流程为初图识别、场景注册、预接近、近景纠偏、闭爪和试提。成功终态为 `held_verified`。此时夹爪可能仍持物，交接或下一轮前请按现场流程放回。以药盒是否真正离面并保持为现场证据，夹持姿态和重复性还要单独记录。

### 悬停转腕拍照试验

从观察位开始，确认空爪，并确认整条预接近路径与悬停处张爪、转腕的扫掠范围有足够留空。保留原标定纸及阿昔洛韦乳膏盒。先预览。

```cmd
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --preview --wrist-probe
```

预览须同时显示 `path_preview_passed` 和「预览2号舵机目标」。只有在现场仍满足条件时才运行下行。

```cmd
"%PY%" -X utf8 .\k210_camera\grasp_controller.py --config "%CFG%" --once wrist_probe_%RANDOM%_%RANDOM% --wrist-probe --confirm-empty --execute
```

流程为预接近到位、重新读取关节并核对留空、转 2 号舵机、拍照。若夹爪还需张开，首段请求一并给 1 号发 372，控制板决定两轴实际起停时间。已采样的腕轴实读范围为 458–536，试验目标留出反馈容差后限制在 461–533。出现 `wrist_probe_completed` 才算这条路线走完。结果 JSON 的 `hover_report` 指向悬停记录，查看其中 `wrist_commands` 的请求、任务终态及新鲜反馈。拍完停在空爪悬停位，需按现场流程回观察位后再做下一轮。每次用新请求 ID，试验记录不可作为继续抓取的接续记录。

## 遇到失败怎么交接

| 日志停在 | 优先核对 |
| --- | --- |
| 场景注册，板位姿或边界失败 | 初图中标定板可见性、药盒是否完整入镜、反光或遮挡。保存原图及观测 JSON。 |
| 预接近路径无解 | 记录是否使用 `--wrist-probe`，以及盒心、台面高度、悬停候选和失败原因。先用预览比较摆位。 |
| 近景匹配失败 | 看盒面是否大面积出画，匹配点是否只聚在一小块，以及板是否能独立定位。 |
| JPEG 数据段提前结束 | 相机单测确认是否重复出现，核对板端固件和电脑波特率。230400 的传输校验通过后仍可能出现 JPEG 解码失败。 |
| 补偿误差超过 10 或任务结果未知 | 保存请求、任务 ID、原规划目标和实读，查空闲状态及实际姿态。结果未知时不要重发动作。 |
| 试提离面失败 | 确认盒子是否还在夹爪，交由现场人员按既定流程放稳。记录闭爪前偏角、关节回读、实际离面和倾斜方向。 |

每轮交接留 **请求 ID、run_id、完整日志、pipeline JSON、实际摆位**。视觉问题附该轮原图和观测 JSON。动作问题附悬停、近端或试提记录。可按运行编号在 `k210_camera/controller_results` 查总控文件，阶段记录在 `k210_camera/vision_grasp_results`。本增量包仅随附源码、动作配置、测试与文档，现场照片和日志按具体轮次另行交接。

## 源码从哪里看

- `grasp_controller.py` 和 `run_current_box_trial.py` 负责入口、请求去重、试验与完整抓取的阶段分流。
- `approach_grasp_candidate.py`、`wrist_roll.py` 和 `calibrate_wrist.py` 负责悬停选点、腕轴命令与现场采样。
- `register_current_scene.py`、`fit_known_box_outline.py`、`grasp_visual_observer.py` 和 `fit_grasp_handeye.py` 负责登记、盒面几何和参考坐标。
- `guarded_visual_approach.py`、`grasp_approach_policy.py`、`tcp_pose_planner.py` 和 `verify_same_box_grasp.py` 负责近端纠偏、规划及夹取验收。`place_and_return.py` 是独立放置入口。
- `grasp_motion_profile.py` 和 `grasp_motion_fixed_placement_trial.json` 是动作参数与参数校验入口。`test_grasp_coordinator.py` 和 `test_wrist_roll.py` 覆盖总控、开度和转腕回归。
