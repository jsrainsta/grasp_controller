# 11 月 18 日前三阶段自动联调交接

这次联调覆盖小车到 B 点停稳、机械臂取药并收臂、小车收到回执后返航。返回后的放药另行联调。截图里“闭爪后由人工确认再通知返航”对应旧流程。当前树莓派入口已经能在同一次调用里完成闭爪、自动收臂检查和返航回执。PiLink 的真车闭环还要双方一起验证。

## PiLink 怎么接

1. 小车导航到 B 点，由小车侧确认 `AT_TARGET_STATIONARY_CONFIRMED`。树莓派上的任务编排拿到停稳确认后，保持底盘停车，再启动抓取入口。抓取脚本依赖上游提供停稳确认。
2. 给每次导航任务分配一个稳定、唯一的 `request_id`，传给抓取脚本。同一任务重复提交同一个 ID 时，抓取端返回已记录的结果。收到异常或超时后保持停车，先查原任务，再决定现场处理。
3. PiLink 等子进程退出，读取标准输出的一条 JSON。过程日志走标准错误。只在**退出码为 0、返回的 `request_id` 与当前任务一致、`status == "stowed_verified"`、`travel_allowed == true`** 同时满足时启动返航。同一任务只启动一次返航。退出码单独为 0 也可能是其他抓取模式的回执。

在树莓派自动版项目目录调用。PiLink 通过标准输入传入这行 JSON，下面的 ID 只是样例。

```bash
cd ~/grasp_pi_7x5_auto_trial
printf '%s\n' '{"type":"arrival","status":"OK","request_id":"B-demo-001","target_id":"med_003"}' |
  .venv/bin/python -X utf8 k210_camera/pi_arrival_grasp.py \
    --config k210_camera/controller_pi_trial.json --execute
```

成功回执的核心字段如下，其余字段用于查日志。

```json
{"request_id":"B-demo-001","status":"stowed_verified","grasp_confirmed":true,"travel_allowed":true}
```

| 回执 | PiLink 处理 |
| --- | --- |
| `stowed_verified` 且符合上面的全部条件 | 启动返航 |
| `awaiting_stow_confirmation`，退出码 3 | 旧模式的待人工确认，保持停车 |
| `held_verified`，退出码可能为 0，`travel_allowed: false` | 保持停车 |
| `failed` 或 `rejected`，退出码 1 或 2 | 保持停车，保存结果和错误 |
| 调用超时、输出缺失、JSON 解析失败或 ID 对不上 | 保持停车，核对原任务的 run ID 和日志 |

## 抓取端部署与验收

- 沿用实测的 7×5 标定板和 `med_003`（阿昔洛韦乳膏）。用小车实测停稳点确认板和药盒在视野内、机械臂够得到。现有流程针对当前药盒和相机安装。
- 在 `controller_pi_trial.json` 填实际的 K210 `camera_port` 和 `arm_url`。K210 使用 `230400`。树莓派直连的机械臂服务参考端口是 `8000`，仓库中的 `18000` 是示例，先按现场地址查 `/v1/arm/status`。保留 `close_only: true` 与 `auto_stow`，用户服务名使用现场部署的 `grasp-arm.service`，由运行抓取的同一用户管理。
- 抓取入口在闭爪反馈通过后重启机械臂服务，等关节和夹爪反馈稳定，再打开 K210 等 15 秒、拍照并严格校验 JPEG，之后检查拍照期间关节变化。重启后 HTTP 暂不可读时，每隔最多 2.5 秒重试回读，沿用原有 25 秒等待窗口。
- 本版采用现场约定的验收口径：取消历史回位关节值比对及照片中蓝色区域宽度门槛。照片只校验解码和尺寸，`grasp_confirmed` 是流程回执字段，无法独立证明照片里仍有药盒。首次联调现场核对收臂位置和持盒状态，再验证自动返航。完整联调前保持底盘停车，使用预览检查摆位。
- JPEG 质量 80 是可选的 K210 固件试验，用于观察坏图频率和识别效果。现有 230400 固件可继续用于接口联调。该改动尚未做板端对照验证。
